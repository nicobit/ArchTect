ArchTect follows the [Structurizr DSL](https://structurizr.com/help/dsl) as its canonical modeling language. This section explains how the DSL behaves inside ArchTect and how models surface in the UI.

## Core concepts

| Concept | What it is | DSL keyword |
|---|---|---|
| **Person** | A human user of the system | `person` |
| **Software System** | A top-level software system | `softwareSystem` |
| **Container** | A deployable unit within a system (API, database, web app) | `container` |
| **Component** | A structural building block within a container | `component` |
| **Relationship** | A connection between elements | `->` |
| **Group** | A named boundary around related elements | `group` |
| **Deployment Node** | An infrastructure host or environment | `deploymentNode` |

## View types

| View type | Shows | Use case |
|---|---|---|
| **System Landscape** | All systems and people | High-level overview |
| **System Context** | One system and its interactions | Scoping a single system |
| **Container** | Containers within a system | Internal structure |
| **Component** | Components within a container | Detailed design |
| **Dynamic** | Interactions over time | Sequence/flow diagrams |
| **Deployment** | Infrastructure and deployment | Operations and DevOps |
| **Filtered** | Subset of another view | Focused communication |
